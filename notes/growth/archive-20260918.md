## In-app event baseline

2.0.0 had no game-event instrumentation. So first-beacon reach, Guardian
kill rate, overcharge success, and next-cycle choice cannot be compared
before/after 2.0.0. 2.1.0 ships the instrumentation code but submits
transmission disabled because a protected collection path is not ready. The
first baseline is made from a later version that verifies App Check or a
protected proxy and re-collects explicit consent.

| Baseline | Active consent | Run start | First beacon | Guardian encounter/kill | Overcharge choose/success/leave | Cash out/continue | Status |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 2.0.0 | — | — | — | — | — | — | events not implemented; do not invent retroactively |
| 2.1.0 | — | — | — | — | — | — | analytics-disabled submit; no export created |

Summarize Firestore export JSON/JSONL with
`pnpm analytics:report -- --file <path> --version <active-version> --to YYYY-MM-DD`.
Play metrics split by event app version, retention by first-consent version,
so a return after an update stays in the original consent cohort. `--to`
must name the UTC observation end date included in the export. Read D1/D7/D30
rates only when the tool's default minimum cohort `n=20` is met; do not
interpret smaller slices. Current public REST rules alone do not stop
spam/cost attacks, so do not start live collection with
`ingestion_hardened` off before App Check or a protected collection path is
verified.
