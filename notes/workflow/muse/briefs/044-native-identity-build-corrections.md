# Brief 044: Make the native identity foundation buildable and truthful

## The ask
The user asked for genuine Google game login, Apple login and a durable guest ID before play in 4.0.0. Continue the native identity round; do not integrate title or cloud gameplay yet.

## Confirmed evidence
- The director ran the standalone identity script: 98 cases passed, followed by six leaked ObjectDB instances and two resources still in use. Node preflight tests passed 11 cases. These do not compile either native implementation.
- The director downloaded the pinned official `play-services-games-v2:20.1.2` AAR and ran `javap` on `GamesSignInClient`. Its only methods are `isAuthenticated()`, `requestServerSideAccess(String, boolean)` and `signIn()`. The Kotlin source calls nonexistent `signInIntent` and `signOut()` methods. Official reference: https://developers.google.com/android/reference/com/google/android/gms/games/GamesSignInClient . Use the actual v2 Task API, not the v1 intent API.
- There is no AndroidManifest plugin registration in the new files. The Gradle template lacks a standalone settings/root/wrapper configuration, and the build entry script only stages identifiers; it cannot build the bridge it names. The iOS SConstruct has no Firebase header paths or pinned Firebase dependency acquisition/link recipe, and does not append the godot-cpp archive into the library/link recipe. The Objective-C++ constructor assigns an Objective-C object directly to a `void *` under ARC. Compile against real headers rather than treating GDScript compilation as native verification.
- No `FirebaseApp`/`FIRApp` initialization is implemented before `FirebaseAuth.getInstance()` / `[FIRAuth auth]`. Without installed Firebase client config these throw rather than returning the promised not-configured state. Check initialization/config safely, for guests as well as providers; Firebase native public client config must actually be staged into exports.
- Both the existing godot-iap export plugin and the new identity export plugin call `add_file` for `res://.godot/extension_list.cfg` with only their own entry. This risks replacing the purchase extension during iOS export. Use one composed list and actual iOS static-library/framework export integration; preserve IAP.
- `ensure_public_id()` returns a new valid ID even when `_save_id()` fails. Its failed-write test asserts this as success. That ID changes on relaunch, contrary to durable ID before play. Expose and enforce durable identity readiness; retain a pending ID for a retry but never advertise an unsaved ID as ready. Also validate schema and bound identity-file length before reading.
- Cancel removes request bookkeeping while native Firebase Tasks still mutate the session; dropping their callback does not undo `signInWithCredential`. Guard every stage before invoking a mutation. Once an irreversible SDK mutation has begun, report a draining/noncancellable state and retain the operation lock until completion rather than claiming cancelled and allowing another sign-in. Preserve the previous identity on sheet cancellation and failed linking. The same rule applies to timeout. The current settled-request sets also grow forever, including synchronous session reads; bound deduplication memory.

## Do
Fix those native/build/persistence contracts and add focused regressions that exercise failure, stale callbacks and the post-mutation cancellation boundary. Supply reproducible build tooling with explicit official dependency versions, checksums or revision pins, correct source/header/link paths, Android plugin discovery and iOS export registration. Public config must remain ignored/export-only, with no secret or token logging. The implementer's network restriction remains: tooling may fetch when the director runs it later, but do not fetch now. Use safe not-configured errors when required native Firebase config is absent. Account/session source tests must clean up their objects and resources.

For iOS identity, an App ID Sign in with Apple entitlement plus the Firebase iOS client configuration is the native requirement; do not incorrectly gate the native sheet solely on a web Services ID. Document server/provider configuration separately. Do not request unneeded personal scopes when no names/emails are used. Preserve safe account-delete reauthentication and revocation.

## Do not
Do not change title, arena, journey, ranking, Firestore rules, project/preset values, existing billing behavior, stores, package identity, guards or workflow files. If composing iOS extension registration requires a small existing export-tool/plugin change, make only that exact change and explain it. Keep original round ownership boundaries otherwise. Do not describe native builds or provider tests as passed; the director performs those.

## Acceptance
Direct-callable identity tests and build-tool tests pass without cleanup errors. Failure to durably write an ID prevents identity-ready/play-ready success across restart; retry persists the same pending ID. Cancellation before credential mutation never switches UID; cancellation after mutation begins does not release the lock or publish fake cancelled success. A repeated session-query stress test leaves bounded request bookkeeping. Dry-run build commands report real missing dependencies/config without values. The director can run explicit Android and physical-device iOS bridge build commands without constructing missing build definitions by hand. Existing IAP extension remains present in exported registration and its regressions pass.

## Judgment
The director repeats tests, compiles from official pinned dependencies, examines produced AAR/static-library symbols and combined export registration, then separately verifies native sheets on devices. Send back concrete build instructions and changed file list, with any remaining setup requirements stated exactly.
