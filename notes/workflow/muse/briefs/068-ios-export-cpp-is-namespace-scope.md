# Brief 068: injected iOS C++ is at namespace scope, not inside plugin init

## Confirmed real-app evidence
Round 064's emitted entry reference is useful, but the registration snippet's assumed insertion context is wrong. The director copied the two helpers into the same disposable complete game fixture, exported again with the real engine/wrapper and built the actual exported iphoneos arm64 app. Export succeeded. Xcode failed at `MoonlitBeacon/dummy.cpp:40:1: error: a type specifier is required for all declarations`.

The real 4.7.1 export template `ios.zip` has `godot_apple_embedded/dummy.cpp`, copyright then **`$cpp_code` at namespace scope**. `add_apple_embedded_platform_cpp_code` appends literal whole-source text. The generated file contains global extern declarations followed by a naked `register_dynamic_symbol(...)` function call, followed by the exporter-generated empty `godot_apple_embedded_plugins_initialize` function. The hook DOES NOT insert statements into that function. A clang test wrapping the shipped snippet in a synthetic function passes the wrong context and cannot prove the actual export.

## Do
Emit complete valid namespace-scope C++ for the actual template. Use the supported engine init callback stage to defer the symbol-table write until engine globals exist: upstream `drivers/apple_embedded/os_apple_embedded.mm` exposes `add_apple_embedded_platform_init_callback(void (*)())`, holds callbacks in zero-initialized primitive globals and invokes them in `OS_AppleEmbedded::initialize`, after construction and before main extension lookup. A static/constructor registration may register only the callback at startup; that callback may register the entry's address later. Verify the locked archive exposes the selected engine function. Do not write to the engine String/hash map from a global constructor, call the GDExtension entry early, duplicate the generated plugin-init function or patch generated Xcode source afterward.

Add meaningful tests that compile the exact whole-source snippet at namespace scope (not wrapped in a test function), preserve the C entry name and retain it in the linked executable, and prove deferred registration runs at the engine callback stage. Keep fallback hook selection/composed extension list tests. Public upstream source and template bytes may be studied as reference; the director performs the complete Godot/Xcode build because that copy lacks deployment config.
