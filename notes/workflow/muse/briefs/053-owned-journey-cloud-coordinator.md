# Brief 053: Connect durable journeys to owned cloud data safely

## The ask
“게스트 로그인도 미리 아이디 받고”, “마지막 플레이 한 구간 저장되서 계속 이어가게”, and “랭크는 캐릭터랑 점수가 잘 나와야하고 플레이어 아이디는 고유로”. Build the game-facing coordinator for these accepted foundations. Presentation/native wiring follows separately.

## Where things stand
The working tree contains accepted Journey/onboarding/story and cloud modules. The director reproduced Journey 428, Vault 206, story 709 and cloud 206 assertions, plus all 37 real Firestore emulator cases. Atomic ID ownership and atomic account-data deletion are already enforced. Native and entry presentation copies are still finishing; do not read/import their files. A future host supplies a durable `MB-` + 32 lowercase hex ID, Firebase UID, token supplier, and receives the canonical ID to persist. Journey currently uses one global main/backup file; CloudIdentity generates another random ID during registration. CloudHall rank cache grows per score; HTTP sender checks response size only after receiving it. Journey cycle cap 99999 differs from cloud cap 9999. No provider or new rules have been enabled/deployed.

## Do
- Add a production-ready Node coordinator under `scripts/cloud/`, with explicit host-injected account/token configuration and signals/state snapshots for account readiness, save status, safe local/remote conflict summaries, actual Hall rows and self rank. Keep native/UI dependencies out. Reserve the supplied durable guest ID for a new UID; never silently replace it on a collision. An existing account returns its canonical ID explicitly. Partition Journey main/backup and revision metadata by public ID, migrate the old local journey once to the first guest without losing bytes, and reject late work from an old account. No gameplay or authentication waits on network.
- Publish a stable-checkpoint notification/hook from Journey only after a successful verified local write. Subscribe to it, coalesce cloud writes, acknowledge only actual successful CAS commits, retry boundedly, and show conflicts without silently choosing. Validate complete downloaded payloads through Journey before any installation. Local-versus-remote choices preserve the rejected version for recovery. Account switches preserve each local journey. No frame-by-frame serialization or background mid-frame writes.
- Prevent cloud restore from minting historical earned currency on this device. Assign/initialize a durable local receipt floor without granting prior remote score; new earned deltas still settle exactly once. Also close the confirmed fallback receipt hole: a string ID evicted from the bounded Vault ledger currently pays again if replayed. Unknown/retired receipts must never mint. Do not mutate the paid entitlement/IAP ledger. Keep tests of normal fresh runs, failed initial Vault save, restart/retry and mixed receipts meaningful; update superseded unsafe expectations with an explicit reason.
- Send actual checkpoint-derived hero/score/cycles into a single best Hall row. Globally throttle rank refresh even while score changes, bound caches, retain and label last known/offline/unregistered data accurately, and suppress old-account results. Match cloud/Journey bounds in modules and additive rules/tests. Bound HTTPRequest body allocation before receipt with the real engine property; cancellation/teardown cannot leave hanging requests applying late state.
- Add focused coordinator tests with injected services and real file writes for offline start, same-ID reservation, account switch, stale callbacks, disk failure, CAS conflict/local/remote choices, malformed/oversized download rejection, remote receipt floor, bounded cache/throttle, and safe restore. Extend real rule tests for changed bounds. Add a standalone test command/tool and integration contract note. Do not register into the shared runner yet.

## Do not
No native/addon files, existing title/arena/HUD/result/scenes, art/assets/manifest, shared runner/package/project/presets, production root Firestore rules/indexes, credentials, network/deployment/store/device/git-history operations. Keep additive rules and all legacy contracts. No fake rankings, fake login success, silently clobbered saves, synced purchase or currency ledgers, billing upgrades, or claims that mocks prove providers.

## Acceptance and director judgment
The director independently runs coordinator and neighboring cloud/Journey/Vault tests, real emulator cases, and a disabled account-generation/receipt guard negative control. Observe file bytes before and after account/conflict operations. Restore starts at the validated gate with growth, remote historical points grant zero currency, subsequent new delta grants once, and retired fallback replay grants zero. New UID reservation uses the exact pre-play ID. Hundreds of score changes produce a bounded request count/cache. No token/UID leaks into public Hall or log/disk. Report exact host contract and runnable test commands. All existing monetary regressions remain meaningful and clean.

Coordinator and bounded service fixes, Journey notification/partition helpers, safe Vault receipt initialization, focused tests and standalone tools, additive rule tests as needed, `notes/plans/4-0-0-cloud-coordinator-log.md`. One task: reliable owned journey orchestration.
